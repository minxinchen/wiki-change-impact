# 實驗：來源更新能否定位待核對 Wiki 頁面

Author: Nio (Master) · Implementation: Codex · 2026-10-09

## 背景與目標

來源整理成 Wiki 後，一份材料可能支撐多個頁面。既有欄位／連結 lint 能指出格式或缺檔，卻不告訴維護者哪些頁面可能沿用舊資料。本實驗檢查兩件事：依賴鏈是否完整傳播更新影響；沒有證據依賴的頁面是否被排除。

設計承接工作站既有產品 schema 的 `sources` 與 Ingest SOP，以及 memory-git-ops 的唯讀 lint 思路。新增部分是內容指紋快照、前後版本依賴聯集、反向 BFS 和附路徑的報告。沒有把歷史研究方案當成已部署系統，也沒有更改正式 Wiki 的規則。

## 材料與方法

### A. 可公開重跑的合成案例

`examples/` 含 4 個 Markdown 頁面、兩版合成規格和一份獨立資料。規格 v1 → 概念 → 產品 → 比較形成三層依賴；儲存注意頁只引用獨立資料，但保留一條 `related` 到產品頁。

`demo.py` 在新的輸出目錄複製案例並建立基準，將概念頁引用由 v1 切至 v2，不改舊來源。第一次比對應列入三頁且排除儲存注意頁。接著腳本修正文句，再與同一基準比對，確認不會自動標記內容已核准。這一步是合成修正，不冒充人工審查。

### B. 現有 Wiki 的唯讀適配

只掃描既有產品 Wiki 的 `wiki/*.md`，解析其中的 `sources`。取樣單位是頁面、追蹤檔案與明確來源邊，不把文件數量當成成果分數。不解析 `related_concepts`（概念 ID）或 `related_evidence`（實證 ID），避免錯當檔案路徑。

為檢查變動影響，把本次快照包含的檔案複製到 temporary directory。按「來源被引用次數最多、同次數以檔案 ID 字典順序」選定一份來源，在複本末尾加入測試標記，再比較前後快照。不是根據受影響頁數挑選結果。結束後清除複本，重新掃描正式 Wiki 核對未變動。

## 結果

| 實驗 | 觀察 | 支持的結論 |
|---|---|---|
| 合成規格版本切換 | 3 頁受影響、1 頁排除 | 能沿明確來源鏈傳播；一般關聯不傳播 |
| 合成文句修正 | 仍為 needs_review | 修改檔案與接受內容是分開的判定 |
| 現有 Wiki 適配 | 23 頁、33 追蹤檔案、48 邊、0 結構問題 | 現有 sources 可轉成可分析的依賴圖 |
| 引用最多來源的隔離變動 | 直接被 18 頁引用；18 頁受影響、5 頁排除 | 多頁共用來源的維護範圍可以被列出 |
| 正式 Wiki 前後比對 | 快照一致 | 本輪掃描與隔離實驗未改動正式材料 |

現有掃描的 10 個非頁面節點是整理過的來源文件。本次圖在這些葉節點停止，沒有證明已追到最初的 raw；更沒有檢查每句話是否忠於原始材料。

## 控制流程驗證

`tests/test_impact.py` 覆蓋：跨 vault、來源版本切換、來源刪除、來源內容變動、循環、無關頁排除、未知 vault、越界與 symlink、YAML 重複鍵、基準格式、設定範圍變更、輸出覆寫、HTML 跳脫及唯讀性。

18 個測試通過。獨立 reviewer 找出「切換兩份已被追蹤的來源時，漏列切換引用的頁面」；已新增每頁來源集合差異檢查，直接列入該頁並保留下游傳播，補對應回歸測試。目錄讀取失敗也會阻擋乾淨結果。

測試不需模型、雲端 API 或正式業務文件。指令：

```sh
.venv/bin/python -B -m unittest discover -s tests -v
```

## 討論與結論

影響分析降低的是「來源改變後不知道要查哪些頁」的不確定性，不能取代事實核對。`sources` 越完整，範圍越可信；缺少來源宣告的正文不會神奇地被找出。使用前後圖聯集能保留已移除關係的影響，也可能產生較保守、跨版本拼接的路徑。

下一個可驗證的擴充應是讓 reviewer 對某份固定 report 與候選頁版本留下審查結果，並在檔案再變動時使核准失效。此版尚未實作這個核准層；不以重新產生 baseline 代替內容審查。
