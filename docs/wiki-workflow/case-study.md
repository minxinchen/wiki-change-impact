# AI_WORKSTATION 協作 Wiki：讓規則保留原因與邊界

[回首頁](../../README.md)

Author: Nio (Master) · Evidence review and editing: Codex · 2026-10-14

## 背景

Agent 長期協作需要重新取用過去的經驗。單純保存聊天不足以讓下一次任務快速找到規則；只留下結論，又可能失去原本成立的條件。

## 問題與目標

現存協作 Wiki 的「記憶保留根因」節點記載：要求審查第三方工具，被記成不安裝第三方工具。這是條件被壓縮為禁令的失真。

目標是將經驗整理成有原因、有邊界、能按任務取用的知識。原始事件保留作為回查依據；Wiki 則幫助 agent 理解下一次該如何判斷。

## 方法

1. 保留事件脈絡，區分原話、整理紀錄與後續解釋。
2. 節點同時寫規則、原因與邊界，避免只剩口號。
3. 索引摘要標明何時需要讀取該節點。
4. 新任務先選擇相關知識，再按需要查原始紀錄。
5. 發現誤解時整合既有節點，保留版本與關係。

以本案例而言，「先審查」保留為條件；「降低未知工具風險」解釋原因；「並非一律禁止」說明邊界。這些是概念化說明，不是完整事件逐字重播。

## 現存證據與限制

協作索引可見觸發條件與內容摘要；規則節點可見 why、反模式與邊界；schema 定義相關、取代、矛盾與細化關係。這些證明有對應的知識設計與文件內容。

本輪沒有重跑當年的失敗，也沒有新 session 前後對照。事件敘述來自現存規則的回顧，未獨立核驗事件發生時的完整工具 trace。因此不宣稱已證明後續行為改善或自動載入可靠性。

## 結論

本案呈現的是一套協作知識的組織方法：保留來源、整合規則、按需取用，再接受校正。讀者應能看懂 agent 如何取得適用知識，以及哪些行為仍需驗證。
