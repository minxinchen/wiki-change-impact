# 案例：知識已更正，查詢入口與來源鏈仍未同步

Author: Nio (Master) · Reconstruction: Codex · 2026-10-10

## 研究背景與目標

既有產品 Wiki 用於讓 Agent 理解產品、準備比較與內容。一次機型比較中，保存紀錄記載：Agent 把必要結構說成可選擴充，使用者指出這個理解錯誤並說明其功能。這不是換一個數字，而是修正「標準結構／選配」的知識分類。

本案目標是追查：校正如何成為 Wiki 知識，又如何被下一次任務取用。判斷來源是保存的領域校正，不把該口述視為第三方工程認證。

## 材料與可驗證程度

| 材料 | 本輪發現 | 證據限制 |
|---|---|---|
| 領域校正紀錄 | 記載原先錯誤、正確分類、功能解釋及未知事項 | 檔內明示「重組整理」，不是完整逐字 transcript |
| Ingest log | 記載更新兩張機型頁及一張概念頁 | 操作敘述；不等於完整 tool trace |
| 舊機型卡與現行機型頁 | 分別存在可擴充／必備兩種表述 | 現存差異；不能單憑它重建歷史先後狀態 |
| 查詢入口與規則 | 一處引導 Wiki，一處優先舊卡 | 實際可讀到衝突；未測發生錯誤的機率 |
| 概念頁與另一張機型頁 | 正文加入校正，sources 和日期未同步 | 可核對的追溯缺口 |

完整來源與行號存於本機審閱包，未提供於 repo。獨立本機 AI reviewer 核對相同來源，確認上述現存缺口；外部讀者目前無法自行驗證私人歷史全文。保留這個限制，不能用摘要或 hash 假裝原始材料已公開。

## 實際流程的還原

1. **問題**：使用者詢問兩機型的定位差異，測試按任務載入。
2. **失敗**：保存紀錄記載 Agent 延用 Wiki 中的錯誤分類。
3. **校正**：使用者指出必要結構不能說成可選，補充功能與定位差異，同時保留沒有依據的數值問題。
4. **整合**：log 記載修訂既有機型頁和概念頁；現行頁面可見修正內容。
5. **仍未閉合**：查詢規則仍指向舊卡；部分頁面未補修正來源。尚未取得當時完整重問與回答驗收紀錄。

這是材料鏈的重建，不是宣稱本輪重新執行過歷史 Agent 流程。

## 結果與討論

原始資料保留、知識分頁與人工校正已有實例。更新後仍存在一致性缺口：知識內容、查詢入口、來源 metadata 沒有共同收斂。是否造成下一次回答錯誤仍待實測。

對 RAG 工作流的含義是：檢索到一份可引用文件，不代表取得的是有效版本；正文看起來已修正，也不代表能追溯到修正依據。若只看 schema 合規或檔案 hash，這兩個問題都可能被漏掉。

使用者的貢獻可由材料支持為：提出具體問題、辨識分類錯誤、補充領域知識、要求保留未知與按需取用。不能把所有架構設計或其效益都歸給使用者，也不能把歷史 log 中「必要條件」「首次成功」的措辭當成已驗證研究結論。

## 結論

這個案例支持一個值得測試的完整問題：**來源校正如何通過知識整合、索引、檢索與回答，且不被舊入口覆蓋。** 已依 [實驗規格](experiment.md)建立隔離比較，見 [真實模型實驗](experiment-2026-10-11.md)。已觀察答案與維護缺口；工作效益及整體品質仍未驗收。
