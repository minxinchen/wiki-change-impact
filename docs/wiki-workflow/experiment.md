# 下一輪實驗規格：同一知識更正能否抵達回答

Author: Nio (Master) · Design: Codex · 2026-10-10

狀態：已依本規格完成首輪局部開發案例，見 [2026-10-11 實測報告](experiment-2026-10-11.md)。以下保留執行前設計；整體維護未通過，不代表整個 Wiki 已驗收。

## 目標

以同一組有來源的材料，觀察 Wiki 整理、入口與更新機制如何影響 Agent 找到證據及產生回答。先驗證一條完整流程，不以一般化準確率為目標。

## 材料與固定條件

- 使用隔離複本，原始 raw、Wiki 與正式入口唯讀。
- 保存完整輸入、文件 hash、問題、角色 prompt、模型識別與執行時間。舊資料快照缺失處明示不可重建。
- 三種條件：A 原始材料搜尋；B 目前 Wiki 入口；C 校正入口與來源鏈後的 Wiki。A/B/C 均限同一知識範圍，不讓 C 偷看額外答案。
- 模型、可用工具、上下文預算與問題固定；各次生成使用獨立上下文。尚未確定實際可執行模型接口前，不填模型結果。
- 每組提供可見檔案 manifest、相對路徑、hash、可用工具、搜尋及讀取上限。B 保留現存入口配置，不能替它挑選最差路徑；C 保留完整修補 diff 供核對。
- 此為案例配置比較：A/B 同時涉及資料表示與檢索策略；B/C 同時修入口和來源。不能把差異歸因於單一因素；要估計個別效果需另做逐項修補比較。C 依已知案例設計，屬開發案例，不稱盲測。
- 小樣本先做流程研究，不以多次相依回答冒充獨立樣本；投入成本只報可取得的實測值。

## 任務與判準

| 問題類型 | 檢查事項 |
|---|---|
| 結構是必備還是選配？ | 明確分類、引用校正來源、不延用舊描述 |
| 兩機型如何區分？ | 按材料中的用途與結構解釋，不僅堆規格或套通用知識 |
| 可以承受多少應力？ | 資料未提供數值時明示未知，不補造數字 |
| 原始材料與 Wiki 表述不同怎麼辦？ | 揭露衝突與版本，不能只挑一個答案忽略另一來源 |

預期答案寫成有來源的主張集合，不硬編一句標準文案。獨立 reviewer 在生成前核對來源立場與未知範圍；事後分開評分主張正確性、引用支撐、漏答、無依據新增及未知處理。AI reviewer 的結果不稱人類 gold。答案主張與評核判準保存在受測 Agent 無法讀取的位置，不放入它的上下文或可搜尋目錄。

## 更新實驗

1. 固定修正前隔離狀態；如不能取得歷史版本，明示為重建實驗，不叫歷史重播。
2. 確認修正前可見材料未含新來源及其衍生修正，再統一注入同一份有來源的新知識交給 Agent，要求判斷受影響的既有頁面。
3. 保存它的實際讀檔、修改、來源與索引/log 更新；檢查 raw 未變及沒有無理由另建平行頁。
4. 新上下文重問相同問題，檢查校正是否抵達答案。
5. Reviewer 核對修改和答案；失敗保留，不換題或倒改預期答案。

## 必須分開的成果

- Retrieval：是否取得相關且有效版本的證據，附實際讀取路徑和摘錄。
- Generation：模型實際回答是否受來源支持，必須保留完整輸出。
- Maintenance：新資料是否整合至既有知識、入口和來源是否同步。

如果只做檢索或手動重建，成果只能標記到該層。不得用預寫答案、作者自演兩種回答、受測模型自稱「讀過」代替實際生成與工具紀錄。

## 完成條件

至少完成一組固定問題的 A/B/C 真實執行，以及一次來源整合後的重問；所有輸入、輸出、review 和失敗可追溯。這仍只支持案例結論；要推廣至整個 Wiki，須另取未參與設計的資料與任務。
