## 知識與任務的分工

| 層 | 保存什麼 | 何時使用 |
|---|---|---|
| Raw | 對話、事件與來源脈絡 | 查證摘要、釐清規則形成原因時 |
| Wiki | 規則、原因、邊界與關係 | 任務需要特定協作知識時 |
| Index | 觸發條件與內容摘要 | 判斷該載入哪些節點時 |
| 任務上下文 | 本次選讀內容與問題 | agent 當次判斷與執行時 |

這是邏輯分工，並不要求所有來源搬到同一實體目錄。既有原始紀錄與協作 vault 分開保存；來源關係需要可追溯，不應僅因檔案放在 raw 就視為正確或逐字紀錄。

## 按需載入

操作規約要求先看索引，再按描述選讀相關節點，必要時讀完整內容或回查原始段落。索引的 description 同時交代何時讀與內容摘要。

本 repo 的 `run.py` 是另一個可供研究使用的受限執行器：預載入口資訊與檔名，模型選擇 search/read，每次最多80行、最多6次讀取與2次搜尋，工具正文上限18,000字元，入口另計。它未強制三層順序，亦未在本案例新增執行驗證。

程式先將小型 corpus 讀入 Python 記憶體；這裡的按需載入指選擇進入模型上下文的內容，不是檔案系統 lazy loading。

## 關係與維護

- `related` 表示導覽關係，不能替代來源依據。
- `supersedes` 表示取代；`contradicts` 表示矛盾；`refines` 表示細化。Schema 有定義不代表所有節點都已補齊。
- 新校正先保留事件，再核對相關節點與索引，避免另生一套無法對齊的規則。
- 使用者與 reviewer 審查知識是否保留原意；程式檢查結構不能替代這項判斷。

## 程式與案例的界線

[變更影響工具](../change-impact-tool.md)分析已宣告的來源依賴；[實驗執行器](../../experiments/wiki-workflow/README.md)提供分段讀取與隔離修改能力。更新檢查器使用特定實驗的欄位規約，不能直接當成協作 vault 的完整 validator。

本作品未將這些元件串成自動維護協作 Wiki 的服務。既有協作知識、輔助程式能力與實際行為驗證分開描述，避免把架構圖當作完成證據。
